# AGY Chrome Bridge

Use Chrome tabs from Antigravity CLI and Antigravity IDE through an MCP server. The extension connects to a local Node.js gateway over WebSocket. No executable is generated, and the existing AGY installation is not replaced.

## Requirements

- Windows, Google Chrome 116 or later, Antigravity CLI, and Node.js 18 or later on `PATH`.
- Load the extension in the Chrome profile you intend to use. Only one profile can connect to the bridge at a time.
- For installation from source, run `npm ci --omit=optional --ignore-scripts` first. Release archives bundle the pure JavaScript `ws` dependency and work without npm or network access.

## Installation

From a release archive, run `powershell -ExecutionPolicy Bypass -File .\install.ps1`. From source, run `powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1`. The installer uses your existing Node.js executable; it does not generate a binary.

The installer copies the Node bridge, gateway, dependency, and extension to `%LOCALAPPDATA%\agy-chrome-bridge`, generates a private pairing token, and adds `agy-chrome-bridge` to AGY's global MCP configuration. It removes only its own obsolete Chrome native host registration. It preserves unrelated MCP servers and backs up replaced files and the MCP configuration; it keeps the two newest `*.backup_*` copies of each kind. If the MCP configuration cannot be parsed (for example, because it contains comments or trailing commas), the installer changes nothing and prints the `agy mcp add` command to run by hand. Close existing AGY sessions and restart the CLI or IDE to reload MCP configuration. If upgrading, exit AGY sessions first; the installer stops its own prior gateway and, if that fails, prints the node process ID to end manually.

In the intended Chrome profile, open `chrome://extensions`, turn on Developer mode, select **Load unpacked**, and choose `%LOCALAPPDATA%\agy-chrome-bridge\extension`. If an older copy is loaded from the source folder, remove that copy before loading the installed folder; the installed folder contains the pairing token. Start AGY CLI or IDE to launch the local gateway. Pairing is automatic: the extension creates a random key for its Chrome profile and connects by itself, and the gateway records the first profile that connects. If the extension is loaded in several profiles, whichever connects first becomes the paired one; load it only in the profile you want AGY to use, or switch with `--unpair` as described below. The toolbar icon shows an **ON** badge while connected. On an HTTP(S) tab, select **Share this tab**. Shared tabs are listed in the popup and can be individually revoked; all shares expire when Chrome closes. If you upgraded, reload the extension in `chrome://extensions` in every profile where it is loaded, because the updated background script takes effect only after reload. Chrome may display a debugging banner while an operation is in progress. If Chrome requests permission for loopback access, grant it from the popup before reconnecting.

Tell AGY to use `browser_tabs`, `browser_snapshot`, `browser_navigate`, `browser_click`, `browser_type`, `browser_key`, `browser_scroll`, or `browser_screenshot`. Observe the page before acting and inspect it again afterward; selectors can become stale as the page changes. The snapshot provides visible text and unique CSS selectors for interactive elements. Navigation waits for the page load event; a dynamic page may require additional time. Screenshots cover the viewport as JPEG images. The extension retries at lower quality and then fails with "Screenshot is too large" if the encoded image still exceeds 800,000 base64 characters. Messages between the extension, the gateway, and AGY are limited to 1 MiB. Chrome internal pages and `file:` URLs are unavailable.

Each shared tab is locked to the origin it had when it was shared. If the tab moves to another origin, for example by following a link, its operations fail with `Tab moved to <origin>`; select **Share this tab** again in the popup to continue. `browser_navigate` likewise refuses URLs on other origins. Re-sharing updates the locked origin. Handle sign-in, CAPTCHAs and consequential decisions through the appropriate user approval or handoff.

## Security and privacy

Sharing grants AGY the ability to read the tab and interact with it, including entering text and clicking buttons. Share only tabs intended for that session, and review consequential actions. Site content is untrusted and must not override the user's instructions. The extension requests Chrome's `debugger`, `tabs`, and `storage` permissions and access to `127.0.0.1`. No remote debugging port is enabled.

The gateway listens only on `127.0.0.1` and accepts WebSocket upgrades only from this extension's origin. A random install secret is stored in the installed extension with a Windows ACL restricted to the current user. Both sides prove knowledge of it using fresh HMAC challenges without sending the secret over the connection. The first Chrome profile that connects is recorded in the ACL-restricted state directory; other profiles cannot take over. A separate random per-launch token and endpoint authenticate MCP clients. Local processes running as the same Windows user can read these secrets and should be trusted.

## Recovery

Remove the extension through Chrome's extension manager. Remove the MCP entry with `agy mcp remove agy-chrome-bridge`, stop the gateway with `node "$env:LOCALAPPDATA\agy-chrome-bridge\bridge\bridge.cjs" --shutdown` in PowerShell, and remove the bridge's own installation directory if no longer needed. To switch Chrome profiles, first close the previously paired profile's extension, then run `node "$env:LOCALAPPDATA\agy-chrome-bridge\bridge\bridge.cjs" --unpair` in PowerShell. It stops the gateway if it is running, deletes `state\paired_profile.json`, and prints what it did; with nothing to do it exits 0. The next profile whose extension connects is then paired automatically. A profile that is not the paired one is refused with close code 4001, and the extension popup shows the `--unpair` instruction. An unreadable `paired_profile.json` also refuses every extension (logged), until `--unpair` resets it. Gateway errors, such as a busy port 38745 or an ACL failure, are appended to `state\gateway.log`, which is capped at about 256 KB and is the file named by the "gateway did not start" message. Backups named `*.backup_*` and `mcp_config.json.backup_agy_chrome_*` can be used to recover prior files; restoring the whole MCP configuration also restores its other entries to that earlier point in time.

## Development

Run `node --check src/bridge.cjs`, `node --check src/gateway.cjs`, `node tests/bridge_test.cjs`, `node tests/extension_test.cjs`, `node tests/popup_test.cjs`, and `python tests/installer_test.py` on Windows. Automated tests exercise MCP routing, token and origin rejection, profile locking, installer rollback, and extension behavior with a simulated browser. They do not replace an end-to-end test in a real Chrome profile.

Increment `extension/manifest.json` for each change. Run `python scripts/package.py` to create a version-matched release archive and SHA-256 checksum in `dist/`. The archive contains the bridge, gateway, installer, extension, README, project license, and the bundled `ws` JavaScript files with their MIT license; it never contains a generated `.exe` or a pairing token.
